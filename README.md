# OrthoGingiva 正畸牙周研究平台测试版

## 立即试用
双击 index.html：浏览器本地演示模式。点“载入示例病例”，进入“牙周随访”，建立一次新随访并录入四牙，提交审核。浏览器演示数据与服务器数据库相互独立。

## 后端＋数据库＋附件
需要 Python 3.9及以上，无第三方依赖。Windows双击“启动测试.bat”，或在本目录运行 `python server.py`，在Chrome/Edge访问 http://127.0.0.1:8765 。

服务只监听127.0.0.1，不能直接用手机访问电脑的这个地址。要跨设备使用，后续需部署HTTPS、用户身份认证及权限体系。本版本没有声称已实现这部分。

后端创建 data/study.sqlite3，附件保存 data/attachments；支持PNG/JPEG/PDF，每个10MB以内。关闭服务后复制整个data文件夹作完整备份。请勿将整个项目目录当作静态网站对外公开；内置服务器只提供白名单静态文件，不提供data目录。

## PWA
通过本机HTTP地址打开后，Edge/Chrome可安装至桌面。PWA只缓存界面，不缓存API响应或文件下载；服务器离线时只读最近记录缓存。需要清除本机研究缓存时，在浏览器开发者工具或站点设置中清理该站点数据。文件双击模式不能注册Service Worker。

## 真实实现范围
患者新建/编辑、四牙CBCT基线登记、多个随访、带符号龈缘位置、缺失原因、疑似事件提示、审核和页面锁定、照片/附件、CSV长表与患者表、JSON记录备份、数据字典、服务器保存日志和版本冲突检查。

临床图片/影像需由用户上传，没有自动CBCT识别、没有风险预测。阈值是示例流程，正式研究前须锁定。桌面模式为响应式页面，非原生EXE。移动端使用横向滚动查看四牙表格。

## 研究数据限制
以研究编号代替身份信息。此版本用于模拟数据/流程测试，后端无远程登录、角色授权和不可篡改的字段级审计；后端拒绝修改或移除已审核随访，但仍不等于具有签名和独立权限的正式研究锁库。JSON记录导出不包含服务器附件及历史全部审计；CSV不含附件。没有实现JSON恢复、服务器与本地演示合并或离线写入同步。

基线含义：必须另建一次“基线”牙周随访；CBCT测量和基线牙周检查为不同数据块。无基线龈缘值时不计算变化。每次随访中疑似事件仅提示，主要研究终点按方案规定的拆除后6个月判定。审核需要医师填写，不把系统提示等同临床诊断。

## 文件结构
- index.html：所有前端界面、样式与本地演示逻辑
- server.py：Python标准库HTTP API、SQLite及附件管理
- manifest.webmanifest / sw.js / icon*：PWA
- data/：启动后创建，非交付示例数据
